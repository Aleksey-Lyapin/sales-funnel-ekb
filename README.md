# Воронка продаж ЕКБ

Сайт: https://aleksey-lyapin.github.io/sales-funnel-ekb/

Дашборд по книге Google «Воронка продаж_Екб» (листы ДНК, ДМД, Алиса — ДДУ; ПИФ). Данные в репозитории не хранятся: их забирает сборка и публикует вместе со страницей на GitHub Pages.

## Как обновляется

- `build.py` читает диапазоны листов через сервисный аккаунт (секрет `GOOGLE_SA_KEY`), вставляет их в `wrapper.html` вместе со страницей `page.html` и кладёт результат в `site/` (`index.html`, `data.json`, `data-hash.txt`).
- Открытая страница сама проверяет `data-hash.txt` при открытии, каждые 30 секунд и при возврате на вкладку. Если данные изменились, она подтягивает `data.json` и перерисовывается без перезагрузки; если изменилась сама страница — перезагружается. Поэтому кэш GitHub Pages (10 минут на `index.html`) не мешает.
- Workflow `.github/workflows/build.yml` запускается:
  - сразу после правки таблицы — задача Планировщика `\BAZA\Воронка ЕКБ - обновление сайта` на рабочем компьютере (C:\Users\baza\sales-funnel\watch_sheet.py) каждые 15 секунд сверяет диапазоны воронки и при изменении отправляет `repository_dispatch` (`sheet-changed`); работает, пока компьютер включён и пользователь вошёл в систему;
  - то же может делать скрипт `apps-script/Code.gs`, если поставить его в саму книгу (не установлен);
  - каждые 5 минут по расписанию — запасной путь (GitHub не гарантирует такие запуски и может их пропускать);
  - при пуше в `main` и вручную (Actions → Build and deploy → Run workflow).
- Если данные и страница не изменились (сравнивается `data-hash.txt` на сайте), публикация пропускается.

## Файлы

- `page.html` — сама страница (та же, что в дашборде на claude.ai); `wrapper.html` — оболочка с заменой рантайма claude.ai (`window.dash`), шрифтами и d3.
- `build.py` — сборка. Локально: `GOOGLE_SA_FILE=путь/к/ключу.json python build.py`.
- `apps-script/Code.gs` — триггер для книги, инструкция в шапке файла.
